Ya sabes escribir una función para cualquier tipo. Ahora quieres Max, que devuelve el mayor de dos valores, y sirva igual para enteros, decimales y textos. Pero any no basta: con un T cualquiera solo puedes hacer lo que todos los tipos permiten, y no todos se pueden ordenar con >. Tienes que decirle a Go qué sabe hacer T.

El concepto

Una restricción es una interfaz que dice qué tipos acepta un parámetro de tipo y, por tanto, qué puedes hacer con él. Go trae tres que usarás a menudo:

  • any: cualquier tipo; no puedes compararlo ni ordenarlo.
  • comparable: los tipos que admiten == y !=.
  • cmp.Ordered, del paquete cmp: números y textos, que admiten < y >.

La restricción es una puerta

Animación: la restricción comparable es una puerta. int, string y bool pasan porque se pueden comparar con ==. []int se queda fuera, y el compilador avisa: []int does not satisfy comparable.

Tu propia restricción

También puedes escribir la tuya. Una interfaz con una unión de tipos, separados por |, acepta solo esos tipos: 

type Number interface {
	~int | ~float64
}

Con T Number, Go sabe que T es un número y te deja usar +, -, * y /. Una interfaz con una unión solo sirve como restricción: no puedes declarar una variable de tipo Number.

Qué significa ~

Puedes crear tus propios tipos a partir de otros, como type Celsius float64. Celsius es un tipo nuevo, pero por debajo es un float64: ese es su tipo subyacente.

float64 sin más acepta solo float64. ~float64 acepta cualquier tipo cuyo tipo subyacente sea float64, así que Celsius también vale.

Fíjate en que Double(Celsius(18.5)) devuelve un Celsius, no un float64: T es el tipo que le pasas, con su nombre. Sin el ~, esa llamada no compilaría.

Un error a propósito

Prueba a escribir Max con any: 

package main

import "fmt"

func Max[T any](a, b T) T {
	if a > b {
		return a
	}
	return b
}
func main() {
	fmt.Println(Max(3, 7))
}
./prog.go:6:5: invalid operation: a > b (type parameter T cannot use operator >)

Cómo leer el error

./prog.go:6:5: invalid operation: a > b (type parameter T cannot use operator >)

Línea 6: a > b no es válido. El motivo va entre paréntesis: el parámetro de tipo T no puede usar el operador >. Da igual que tú lo llames con números: la restricción any no promete que T se pueda ordenar. Cambia any por cmp.Ordered y compila.

El error típico

Olvidar el ~. En el ejemplo, quita los dos de Number: 

type Number interface {
	int | float64
}
./prog.go:16:46: Celsius does not satisfy Number (possibly missing ~ for float64 in Number)

Celsius no es float64, solo lo es por debajo. El propio compilador te sugiere la solución: falta el ~.
