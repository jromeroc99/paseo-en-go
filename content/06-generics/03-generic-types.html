Las funciones genéricas evitan copiar código, pero los tipos también se repiten. En el módulo anterior escribiste una lista enlazada de int. Si mañana necesitas una de string, ¿escribes otro struct igual, con otros métodos iguales? Lo que cambia es solo el tipo del valor que guarda cada nodo.

El concepto

Un tipo también puede tener parámetros de tipo. Esta lista guarda valores de cualquier tipo T: 

type List[T any] struct {
	next *List[T]
	val  T
}

Dentro, T se usa como cualquier otro tipo. Fuera, tienes que decir cuál es: List[int] y List[string] son dos tipos distintos, hechos con el mismo molde.

Los métodos

Un método de un tipo genérico repite el parámetro de tipo en el receptor, sin la restricción: 

func (l *List[T]) Push(v T) *List[T]

Así el método sabe qué es T y puede usarlo en sus parámetros y en lo que devuelve. Cuando llamas a Push en una *List[int], T es int.

El valor cero de T

A veces un método tiene que devolver un T que no existe; por ejemplo, al sacar un valor de una pila vacía. No puedes escribir 0 ni "", porque no sabes qué tipo es T. Declara una variable sin valor y Go le da el valor cero de su tipo: 

var zero T
return zero, false

Si T es int, zero vale 0; si es string, vale "".

Fíjate

Has escrito List una sola vez y la has usado con dos tipos. Cada Push pone el valor delante, por eso el último que metes es el primero que sale. Y Go comprueba los tipos: en nums no puedes meter un string, porque es una List[int].

Un error a propósito

¿Qué pasa si usas List sin decir de qué tipo es? 

package main

import "fmt"

type List[T any] struct {
	next *List[T]
	val  T
}
func main() {
	var l List
	fmt.Println(l)
}
./prog.go:11:8: cannot use generic type List[T any] without instantiation

Cómo leer el error

./prog.go:11:8: cannot use generic type List[T any] without instantiation

Línea 11: no puedes usar el tipo genérico List[T any] sin instanciarlo, es decir, sin darle un tipo a T. List a secas es solo el molde. Escribe var l List[int] y compila.

El error típico

Olvidar el [T] en el receptor. En el ejemplo, cambia la primera línea de Push por esta: 

func (l *List) Push(v T) *List[T] {
./prog.go:12:10: cannot use generic type List[T any] without instantiation
./prog.go:12:23: undefined: T
./prog.go:13:15: undefined: T

Es el mismo error de antes, ahora en el receptor. Y como el receptor no nombra T, el método no sabe qué es: undefined: T.
