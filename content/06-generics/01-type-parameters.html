Quieres buscar un número en un slice de int. Escribes la función, y funciona. Luego necesitas lo mismo para un slice de string, y escribes otra igual, cambiando solo los tipos. Y otra para float64. Tres copias del mismo código: si arreglas un fallo en una, tienes que acordarte de las otras dos. 

func IndexInts(s []int, x int) int
func IndexStrings(s []string, x string) int
func IndexFloats(s []float64, x float64) int

El concepto

Con un parámetro de tipo escribes la función una vez y el tipo queda como un hueco. Va entre corchetes, antes de los parámetros normales: 

func Index[T comparable](s []T, x T) int

Léelo así: T es un tipo que aún no sabes, y comparable es su restricción: T tiene que poder compararse con ==. Después, s es un slice de T y x es un T. Una función así se llama genérica.

Lo que hace el compilador

Animación: Index[T] es un molde con un hueco para T. Al llamarla con un []int, el compilador deduce que T es int y escribe la función Index[int], que imprime 1. Al llamarla con un []string, escribe otra, Index[string], que imprime 2. De un molde salen dos funciones.

Un error a propósito

¿Por qué comparable y no any, que acepta cualquier tipo? Pruébalo: 

package main

import "fmt"

func Contains[T any](s []T, x T) bool {
	for _, v := range s {
		if v == x {
			return true
		}
	}
	return false
}
func main() {
	fmt.Println(Contains([]int{10, 20, 30}, 20))
}
./prog.go:7:6: invalid operation: v == x (incomparable types in type set)

Cómo leer el error

./prog.go:7:6: invalid operation: v == x (incomparable types in type set)

Línea 7: v == x es una operación no válida. El motivo va entre paréntesis: entre los tipos que acepta any hay algunos que no se pueden comparar, como los slices o los maps. Go comprueba la función genérica para todos los T posibles, no solo para el int que le pasas. Con comparable compila.

El error típico

Pensar que cada argumento puede llevar su propio tipo. En el ejemplo, cambia la primera llamada por esta: 

fmt.Println(Contains([]int{10, 20, 30}, "20"))
./prog.go:15:42: cannot use "20" (untyped string constant) as int value in argument to Contains

El slice ya ha decidido que T es int, así que x también tiene que ser un int.
