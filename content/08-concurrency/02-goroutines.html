Los hilos del sistema son caros: cada uno reserva memoria para su stack, y pasar de uno a otro lleva tiempo. Un programa con miles de hilos pesa mucho. Pero un servidor web quiere atender a miles de clientes a la vez. Go tiene su propia forma de hacerlo.

El concepto

Una goroutine es una función que se ejecuta a la vez que el resto del programa. Es muy ligera: empieza con un stack de pocos KB, y puedes crear miles. Todas comparten la memoria del programa.

Se arranca con go delante de una llamada: go say("hola"). El programa no espera a que termine y sigue con la línea siguiente.

main también es una goroutine. Cuando termina, el programa acaba, aunque queden otras.

Arrancar y esperar

Animación: main arranca dos goroutines con go say. Si main termina enseguida, las dos desaparecen sin imprimir nada. Con un sync.WaitGroup, wg.Add(2) apunta dos pendientes, cada goroutine llama a wg.Done() al acabar y wg.Wait() espera a que el contador llegue a 0.

Esperar con un WaitGroup

Un sync.WaitGroup cuenta las goroutines pendientes:

  • wg.Add(n) suma n al contador.
  • Cada goroutine llama a wg.Done() al acabar, y resta uno.
  • wg.Wait() espera hasta que el contador llega a 0.

Pásalo siempre con un puntero, &wg. Si lo copias, cada copia cuenta por su lado y Wait no se entera.

Un error a propósito

Te olvidas de los paréntesis del final: 

package main

import (
	"fmt"
	"time"
)

func main() {
	go func() {
		fmt.Println("hola")
	}
	time.Sleep(time.Second)
}

Cómo leer el error

./main.go:9:5: expression in go must be function call

Línea 9, columna 5: justo donde está go. «La expresión de un go tiene que ser una llamada a una función». Escribir func() { ... } solo define la función; los () del final la llaman. Así que escribe go func() { ... }().
