Mil goroutines suman uno a un contador. Al final debería valer 1000. Lo ejecutas tres veces y sale 967, 958 y 970. Ningún error, ningún aviso: simplemente se pierden sumas, y cada vez un número distinto.

El concepto

count++ parece una sola cosa, pero son tres: leer el valor, sumarle uno y escribirlo. Si dos goroutines leen a la vez el mismo valor, las dos escriben lo mismo y se pierde una suma. Es una data race (carrera de datos).

Un sync.Mutex es un cerrojo. mu.Lock() lo cierra y mu.Unlock() lo abre. Si otra goroutine ya lo tiene cerrado, Lock espera, así que solo una a la vez ejecuta el código de en medio.

Una carrera

Animación: g1 y g2 leen count, que vale 0. Las dos le suman uno y escriben 1: se ha perdido una suma. Con un Mutex, g1 cierra el cerrojo, y g2 espera hasta que g1 escribe 1 y lo abre. Entonces g2 lee 1 y escribe 2. count acaba valiendo 2.

Un error a propósito

Go trae un detector de carreras. Ejecuta el ejemplo con go run -race .: 

==================
WARNING: DATA RACE
Read at 0x00c000112028 by goroutine 9:
  main.main.func1()
      .../race/main.go:15 +0x7b

Previous write at 0x00c000112028 by goroutine 11:
  main.main.func1()
      .../race/main.go:15 +0x8d

Goroutine 9 (running) created at:
  main.main()
      .../race/main.go:13 +0x78
==================

Cómo leer el error

Read at 0x00c000112028 by goroutine 9:
      .../race/main.go:15 +0x7b
Previous write at 0x00c000112028 by goroutine 11:
      .../race/main.go:15 +0x8d

«Carrera de datos»: la goroutine 9 lee una dirección de memoria que la goroutine 11 acaba de escribir, y ninguna ha esperado a la otra. Las dos en la línea 15, count++. Debajo te dice dónde se creó la goroutine: la línea 13, el go func(). Al final imprime la cuenta, Found 2 data race(s) y acaba con exit status 66 para avisarte.

Fíjate en que solo protege count++: lo que está entre Lock y Unlock. Con go run -race ya no hay ningún aviso. Si una función tiene varios return, escribe defer mu.Unlock() justo después del Lock, para no dejar nunca el cerrojo cerrado.

El error típico

Copiar el Mutex con un receptor por valor: 

type Counter struct {
	mu    sync.Mutex
	count int
}

func (c Counter) Inc() {
	c.mu.Lock()
	c.count++
	c.mu.Unlock()
}

Lo que dice go vet

main.go:13:9: Inc passes lock by value: contador.Counter contains sync.Mutex

«Inc pasa el cerrojo por valor». Con un receptor por valor, cada llamada recibe una copia de Counter, con su propio Mutex y su propio count: cierra una copia del cerrojo y suma en una copia del contador. Usa un receptor puntero, func (c *Counter) Inc().
