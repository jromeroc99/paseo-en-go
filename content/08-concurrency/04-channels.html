Las goroutines van a la vez, pero a menudo una necesita el resultado de otra. Podrían compartir una variable, pero eso es peligroso, como verás más adelante. Go propone otra idea: no te comuniques compartiendo memoria; comparte memoria comunicándote.

El concepto

Un channel (canal) es un tubo con tipo por el que una goroutine envía valores a otra. Se crea con make: ch := make(chan int).

ch <- v envía v por el canal y v := <-ch recibe un valor. La flecha indica hacia dónde va el dato.

En un canal sin buffer, enviar espera a que alguien reciba, y recibir espera a que alguien envíe. Así las dos goroutines se sincronizan solas.

Enviar y recibir

Animación: main crea un canal sin buffer y arranca una goroutine. main llega a <-ch y espera. La goroutine envía "ping"; el valor pasa de una a otra y main imprime ping.

Un error a propósito

Envías y recibes en la misma goroutine: 

package main

import "fmt"

func main() {
	ch := make(chan int)
	ch <- 1
	fmt.Println(<-ch)
}

Cómo leer el error

fatal error: all goroutines are asleep - deadlock!

goroutine 1 [chan send]:
main.main()
	.../main.go:7 +0x36
exit status 2

«Todas las goroutines están dormidas»: es un deadlock (bloqueo mutuo). Todas esperan algo que nadie va a hacer, así que Go para el programa. Debajo dice qué hacía cada una: la goroutine 1, main, estaba enviando (chan send) en la línea 7. Nadie podía recibir, porque quien iba a hacerlo era ella misma.

El error típico

Declarar el canal y olvidar el make: 

var ch chan int // vale nil: no hay canal
go func() { ch <- 1 }()
fmt.Println(<-ch)

Enviar o recibir por un canal nil espera para siempre. Go acaba con el mismo deadlock, pero el mensaje te da la pista: goroutine 1 [chan receive (nil chan)]. Crea siempre los canales con make.
