Con <-ch esperas en un solo canal. Pero a veces el resultado puede llegar por varios sitios: un canal con datos, otro que avisa de que hay que parar, un reloj que dice que ya has esperado bastante. Necesitas esperar en todos a la vez y quedarte con el primero.

El concepto

select se parece a un switch, pero cada case es un envío o una recepción por un canal. select espera hasta que uno de ellos puede hacerse, y ejecuta ese.

Si hay varios listos a la vez, elige uno al azar, para que ninguno se quede siempre atrás.

Con un caso default, select no espera: si ningún canal está listo, ejecuta default y sigue.

Esperar en varios canales

Animación: select mira los canales a y b. Ninguno tiene un valor, así que ejecuta default e imprime nada listo. Más tarde llega un 7 por b; ahora ese caso está listo y select imprime b 7.

Un error a propósito

Un select sin default y sin nadie que envíe: 

package main

import "fmt"

func main() {
	a := make(chan string)
	b := make(chan string)
	select {
	case msg := <-a:
		fmt.Println("a:", msg)
	case msg := <-b:
		fmt.Println("b:", msg)
	}
}

Cómo leer el error

fatal error: all goroutines are asleep - deadlock!

goroutine 1 [select]:
main.main()
	.../main.go:8 +0xa5
exit status 2

El mismo deadlock de siempre, pero ahora la goroutine 1 está en [select]: esperaba en la línea 8, la del select. Ninguno de sus canales iba a recibir nunca nada, porque no hay ninguna otra goroutine que envíe.

El error típico

Meter un select con default en un bucle para esperar: 

for {
	select {
	case v := <-ch:
		fmt.Println(v)
		return
	default:
		// nada listo: vuelve a mirar
	}
}

Funciona, pero mantiene un núcleo ocupado dando vueltas sin hacer nada. Si quieres esperar, quita el default: select espera sin gastar núcleo.
