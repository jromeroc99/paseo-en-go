En un canal sin buffer, quien envía se queda esperando hasta que alguien recibe. A veces no quieres eso: una goroutine produce rápido, otra procesa más despacio, y te basta con que los valores esperen en una cola mientras tanto.

El concepto

Un canal con buffer tiene sitio para guardar valores. El tamaño va como segundo argumento de make: ch := make(chan int, 2).

Enviar solo espera si el buffer está lleno; recibir solo espera si está vacío. Los valores salen en el mismo orden en que entraron, como en una cola.

len(ch) dice cuántos valores esperan dentro y cap(ch), cuántos caben.

El buffer

Animación: un canal con dos huecos. main envía 1 y 2, que entran en el buffer sin esperar. Al enviar 3 el buffer está lleno y main espera. Otra goroutine recibe el 1, el primero que entró; queda un hueco, el 2 avanza, el 3 entra y main sigue.

Un error a propósito

Envías un valor más de los que caben: 

package main

import "fmt"

func main() {
	ch := make(chan int, 2)
	ch <- 1
	ch <- 2
	ch <- 3
	fmt.Println(<-ch)
}

Cómo leer el error

fatal error: all goroutines are asleep - deadlock!

goroutine 1 [chan send]:
main.main()
	.../main.go:9 +0x58
exit status 2

Es el mismo deadlock que con un canal sin buffer, solo que llega más tarde. chan send en la línea 9: el tercer envío. Los dos huecos ya estaban llenos, así que main esperó a que alguien recibiera, y no había nadie más.

El error típico

Usar el buffer para tapar un deadlock. Si tu programa se bloquea y le das un buffer más grande, puede que funcione... hasta que lleguen más valores de los que caben.

El buffer no sustituye a una goroutine que reciba: solo deja que quien envía se adelante un poco. Elige su tamaño porque sabes cuántos valores van a esperar, no para que el error desaparezca.

Tu turno

Un canal con buffer también sirve para limitar cuántas cosas pasan a la vez: cada hueco es un permiso. Escribe en limit.go una función que ejecuta cada tarea en su goroutine, pero nunca más de limit a la vez. 

func RunLimited(tasks []func(), limit int)

Hasta que la escribas, go test falla con undefined: RunLimited. Es normal; es tu punto de partida.
