Cuando llamas a una función, Go le pasa una copia de cada argumento. Si la función cambia esa copia, tu variable no se entera. A veces eso es justo lo que quieres. Otras veces necesitas que la función cambie tu variable, y para eso tiene que saber dónde vive.

El concepto

Cada variable ocupa un sitio en la memoria del ordenador, y ese sitio tiene una dirección. Un pointer (puntero) es un valor que guarda la dirección de otro valor. Su tipo se escribe con un asterisco: *int es «un puntero a un int».

  • &x te da la dirección de x.
  • *p sigue el puntero y te da el valor al que apunta. Con *p = 21 cambias ese valor.

El valor cero

El valor cero de un puntero es nil: un puntero que todavía no apunta a nada. A diferencia de C, Go no tiene aritmética de punteros: no puedes sumar 1 a una dirección para saltar al valor de al lado.

En la memoria

Animación: i guarda 42 en una caja de memoria con su dirección. p guarda esa dirección y apunta a i. Con *p = 21 el 21 llega a i siguiendo la flecha. q vale nil y no apunta a nada.

Un error a propósito

Seguir un puntero que vale nil no tiene sentido: no hay ningún valor al otro lado. Este programa compila, pero falla al ejecutarlo: 

package main

import "fmt"

func main() {
	var p *int
	fmt.Println(*p)
}
panic: runtime error: invalid memory address or nil pointer dereference

Cómo leer el error

panic: runtime error: invalid memory address or nil pointer dereference

Un panic es un error que detiene el programa mientras se ejecuta. El mensaje se lee así: runtime error (error en ejecución), dirección de memoria no válida, nil pointer dereference (has seguido un puntero nil). Cuando lo veas, busca qué puntero no apuntaba a nada.

El error típico

Pasar el valor cuando querías pasar la dirección. Si una función recibe un int y le suma 1, solo cambia su copia: 

func increment(n int) { n++ }   // cambia la copia
func incrementPtr(n *int) { *n++ } // cambia el original

Para la segunda versión llamas a incrementPtr(&x), con &. Si te olvidas, el compilador te avisa, porque un int no es un *int.
