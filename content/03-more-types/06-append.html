Lees números de un archivo y no sabes cuántos hay. Un slice creado con make tiene un tamaño fijo y no puede pasar de su capacidad. Necesitas una forma de añadir elementos al final según van llegando.

El concepto

La función append añade elementos al final de un slice: 

s = append(s, 1)
s = append(s, 2, 3, 4)

Fíjate en que append no cambia el slice que le pasas: devuelve uno nuevo, y tú lo guardas otra vez en s. Hay una buena razón. Si el array de debajo tiene sitio, append escribe ahí y devuelve un slice más largo. Si no cabe, crea un array más grande, copia los elementos y devuelve un slice sobre ese array nuevo. En los dos casos, el resultado es el único slice que tiene la longitud correcta.

append también funciona con un slice nil, así que puedes empezar con var s []int y añadir desde ahí.

Mira la capacidad: cada vez que se queda corta, Go reserva un array mayor. Cuánto mayor exactamente es un detalle interno de Go; no escribas código que dependa de ese número.

Un error a propósito

Como el resultado de append es lo único que importa, Go no te deja tirarlo: 

package main

import "fmt"

func main() {
	s := []int{1, 2, 3}
	append(s, 4)
	fmt.Println(s)
}
./prog.go:7:2: append(s, 4) (value of type []int) is not used

En la línea 7, el compilador te dice que append(s, 4) produce un valor de tipo []int que nadie usa. La solución es guardarlo: s = append(s, 4).

El error típico

Guardar el resultado en otra variable y seguir usando la vieja: 

more := append(s, 4)
fmt.Println(len(s), len(more)) // 3 4

Esto compila, pero s sigue teniendo longitud 3: el cuarto elemento solo está en more. Salvo que quieras dos slices distintos a propósito, escribe siempre s = append(s, x): la misma variable a los dos lados.
