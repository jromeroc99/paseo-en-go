Una app del móvil no quiere una página web: quiere datos que pueda leer un programa. Si el servidor responde 16 en texto, ¿cómo envía una lista de tareas, cada una con su número y su título?

El concepto

Con JSON, un formato de texto para datos: {"a": 2, "b": 3}. Un servidor que recibe y responde JSON es una API.

encoding/json convierte un struct en JSON y al revés. La etiqueta `json:"a"` junto a un campo dice qué nombre tiene en el JSON. El código de estado dice cómo ha ido: 200 bien, 201 creado, 400 petición mal hecha, 404 no existe.

Ejecuta el servidor y envía un JSON con -d:

$ curl -i -d '{"a":2,"b":3}' localhost:8080/sum
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 27 Nov 2026 11:14:29 GMT
Content-Length: 13

{"result":5}

Fíjate en que -d hace un POST con ese cuerpo, y en que el campo Result sale como result, el nombre de su etiqueta.

Un JSON que no lo es

$ curl -i -d 'dos' localhost:8080/sum
HTTP/1.1 400 Bad Request
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 11:14:30 GMT
Content-Length: 16

JSON no válido

Decode devuelve un error y el handler responde 400: la culpa es de la petición, no del servidor.

Un error a propósito

Escribir el campo con minúscula:

type sumResponse struct {
	result int `json:"result"`
}
$ go vet .
main.go:15:2: struct field result has json tag but is not exported

Cómo leer el error

main.go:15:2: struct field result has json tag but is not exported

El campo result de la línea 15 tiene etiqueta JSON, pero no está exportado: empieza por minúscula. encoding/json es otro paquete, así que solo ve los campos que empiezan por mayúscula. El programa compila, pero responde {}. Ejecuta go vet: avisa de lo que el compilador deja pasar.

El error típico

Poner la cabecera después de escribir el cuerpo:

json.NewEncoder(w).Encode(sumResponse{Result: req.A + req.B})
w.Header().Set("Content-Type", "application/json")
HTTP/1.1 200 OK
Date: Fri, 27 Nov 2026 11:14:33 GMT
Content-Length: 13
Content-Type: text/plain; charset=utf-8

{"result":5}

Las cabeceras ya se habían enviado, así que el cliente cree que es texto. Pon las cabeceras primero.

Tu turno

Escribe en todos.go una API de tareas. GET /todos responde la lista ([] si está vacía); POST /todos crea una tarea con {"title": "..."} y responde 201; DELETE /todos/{id} la borra y responde 204. Un JSON roto, un título vacío o un id que no es un número dan 400; un id que no existe, 404. Protege la lista con un sync.Mutex.

Lo que escribes

type Todo struct {
	ID    int    `json:"id"`
	Title string `json:"title"`
}
