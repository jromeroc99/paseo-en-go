Ya has escrito un servidor HTTP a mano: leer líneas, buscar la línea en blanco, contar los bytes del cuerpo. Funciona, pero es fácil equivocarse, y aún faltan muchas cosas: leer el cuerpo, elegir qué código hacer según la ruta, atender peticiones que llegan a la vez. ¿Hay que escribir todo eso cada vez?

El concepto

No. El paquete net/http de la biblioteca estándar ya lo hace. Tú escribes un handler, una función que recibe la petición (*http.Request) y escribe la respuesta (http.ResponseWriter).

Un http.ServeMux elige qué handler atiende cada petición según un patrón como "GET /square/{n}": el método, la ruta y los trozos variables entre llaves, que lees con r.PathValue.

Cuando algo va mal

$ curl -i localhost:8080/square/cuatro
HTTP/1.1 400 Bad Request
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Fri, 27 Nov 2026 11:14:21 GMT
Content-Length: 19

n no es un número

http.Error escribe el código de estado y el mensaje. Fíjate en el return que lo sigue: el handler tiene que terminar ahí.

Lo que hace el ServeMux

$ curl -X POST localhost:8080/square/4
Method Not Allowed
$ curl localhost:8080/cube/4
404 page not found

Sin escribir nada más: un POST a una ruta que solo acepta GET recibe un 405, y una ruta que no existe, un 404.

Un error a propósito

Escribir el cuerpo y después el código de estado:

func create(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "creada")
	w.WriteHeader(http.StatusCreated)
}
2026/11/27 12:14:22 http: superfluous response.WriteHeader call from main.create (main.go:11)

Cómo leer el error

http: superfluous response.WriteHeader call from main.create (main.go:11)

Superfluous significa que sobra: la llamada a WriteHeader de la línea 11 no sirve. Al escribir el cuerpo, net/http envió la primera línea y las cabeceras con un 200, y lo enviado ya no se puede cambiar. El cliente recibe 200 OK. Llama a WriteHeader antes de escribir el cuerpo.

El error típico

Olvidar el return después de http.Error:

if err != nil {
	http.Error(w, "n no es un número", http.StatusBadRequest)
}
fmt.Fprintln(w, n*n)
$ curl localhost:8080/square/cuatro
n no es un número
0

http.Error no para el handler: escribe y sigue. Termina tú con return.
