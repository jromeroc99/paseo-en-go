Hasta ahora has guardado números sin preguntarte dónde ni cuánto sitio ocupan. Pero un int8 y un int64 no son iguales por dentro, y si un número no cabe en su tipo pasan cosas raras. Para entenderlo hay que mirar la memoria de cerca.

El concepto

La memoria del ordenador es una fila enorme de bytes. Un byte son 8 bits y guarda un número del 0 al 255. Cada byte tiene una dirección, y las direcciones van seguidas.

El tipo de una variable dice cuántos bytes ocupa: un int8 ocupa 1, un int32 ocupa 4 y un int64 ocupa 8. Cuantos más bytes, más grande es el número que cabe.

En la memoria

Animación: dos filas de ocho bytes con su dirección. a, un int8, ocupa un byte. b, un int32, ocupa cuatro y empieza en el byte 4, así que quedan tres libres. c, un int64, ocupa la segunda fila entera.

Un error a propósito

Un int8 va de -128 a 127. ¿Qué pasa si le das 200? 

package main

import "fmt"

func main() {
	var x int8 = 200
	fmt.Println(x)
}
./prog.go:6:15: cannot use 200 (untyped int constant) as int8 value in variable declaration (overflows)

Cómo leer el error

./prog.go:6:15: cannot use 200 (untyped int constant) as int8 value in variable declaration (overflows)

Línea 6, columna 15: justo donde está el 200. «No puedo usar 200 como valor int8»; el final, overflows, significa que se desborda: no cabe en un byte con signo. El compilador lo ve porque 200 es una constante escrita en el código.

El error típico

Si el número crece mientras el programa se ejecuta, el compilador no puede verlo. El valor da la vuelta, como un cuentakilómetros, y nadie te avisa:
