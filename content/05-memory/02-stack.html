Cuando una función llama a otra, Go tiene que recordar muchas cosas: las variables de cada función, sin mezclarlas, y a dónde volver cuando la llamada termina. Y si una función se llama a sí misma, cada llamada necesita sus propias variables. ¿Dónde guarda todo eso?

El concepto

En el stack (la pila). Cada llamada recibe un frame: un trozo de memoria con sus parámetros y sus variables locales. Llamar a una función apila un frame encima; volver de ella lo quita.

Funciona como una pila de platos: solo tocas el de arriba. Por eso es muy rápido, y por eso las variables de una función dejan de existir cuando vuelve.

Un error a propósito

Una función que se llama a sí misma es recursiva. Esta no para nunca, así que apila frames sin fin: 

package main

import "fmt"

func countdown(n int) int {
	return countdown(n - 1)
}

func main() {
	fmt.Println(countdown(3))
}
runtime: goroutine stack exceeds 1000000000-byte limit
fatal error: stack overflow

Cómo leer el error

runtime: goroutine stack exceeds 1000000000-byte limit
fatal error: stack overflow

Compila bien, pero falla al ejecutarse. El stack tiene un límite, aquí 1000 millones de bytes, y cada llamada lo llena un poco más. Stack overflow significa que la pila se ha desbordado. Una goroutine es la tarea que ejecuta tu código; las verás en el módulo de concurrencia.

El error típico

Toda función recursiva necesita un caso base: una condición en la que vuelve sin llamarse otra vez. El error típico es escribirlo, pero de forma que nunca se cumpla: 

func countdown(n int) {
	if n == 0 { // con n = 3: 3, 1, -1, -3... nunca vale 0
		return
	}
	countdown(n - 2)
}

Con n <= 0 el caso base sí se cumple.
