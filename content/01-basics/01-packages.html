Un programa de verdad no cabe en un solo archivo, y tampoco hace falta escribirlo todo desde cero. Calcular una raíz cuadrada, imprimir texto o leer un archivo son tareas que ya ha resuelto otra persona. Go organiza ese código reutilizable en packages (paquetes: carpetas de código con un nombre), y tú los traes a tu programa con import.

El concepto

Todo archivo de Go empieza diciendo a qué paquete pertenece. Los programas que ejecutas empiezan en la función main del paquete main.

Para usar otro paquete, lo importas por su ruta. El nombre que escribes en el código es el último elemento de esa ruta: si importas "math/rand", lo usas como rand. Cuando importas varios, lo habitual es agruparlos entre paréntesis.

Dentro de un paquete, un nombre es exported (exportado: visible desde fuera del paquete) cuando empieza por mayúscula. math.Sqrt y math.Pi son exportados. Lo que empieza por minúscula solo existe dentro de su propio paquete.

Un error a propósito

Fíjate en qué pasa si escribes pi en minúscula:

package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println(math.pi)
}
./prog.go:9:19: undefined: math.pi (but have Pi)

Así se lee: en el archivo prog.go, línea 9, columna 19, el nombre math.pi no existe. El compilador incluso te da la pista: el paquete sí tiene Pi. Desde fuera de math solo ves los nombres que empiezan por mayúscula.

El error típico

Importar un paquete y no usarlo. En otros lenguajes es un aviso; en Go es un error de compilación, para que no quede código muerto: 

package main

import (
	"fmt"
	"math"
)

func main() {
	fmt.Println("hola")
}
./prog.go:5:2: "math" imported and not used

La solución es borrar el import que sobra. La mayoría de editores con soporte para Go lo hacen solos al guardar el archivo.
