Si tienes que sumar dos números en diez sitios distintos de tu programa, no quieres escribir la misma operación diez veces. Le pones un nombre una vez y la llamas cuando la necesites. Eso es una función.

El concepto

Una función recibe cero o más parámetros y puede devolver un resultado. En Go el tipo se escribe después del nombre: 

func add(x int, y int) int

Se lee de izquierda a derecha: «la función add recibe x, que es un int, e y, que es un int, y devuelve un int». El tipo del resultado va al final, antes de la llave.

Cuando dos o más parámetros seguidos comparten tipo, puedes escribirlo una sola vez: x, y int significa lo mismo que x int, y int.

Un error a propósito

La firma de una función es una promesa. Si dices que devuelves un int, el compilador comprueba que cumples: 

package main

func add(x, y int) int {
	return "suma"
}

func main() {
	add(1, 2)
}
./prog.go:4:9: cannot use "suma" (untyped string constant) as int value in return statement

En la línea 4, columna 9, el compilador encuentra un texto (string constant) donde esperaba un int, justo en el return. El error aparece antes de ejecutar nada: Go lo detecta al compilar.

El error típico

Si vienes de C o de Java, tus dedos escribirán el tipo antes del nombre: func add(int x, int y). En Go eso no compila. Recuerda el orden: primero el nombre, luego el tipo. Con declaraciones largas es más fácil de leer, porque el nombre siempre va primero.
