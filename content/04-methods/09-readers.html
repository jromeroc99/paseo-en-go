Un archivo, una conexión de red, un texto en memoria, un archivo comprimido. Son cosas muy distintas, pero todas tienen datos que se leen poco a poco. En Go se leen todas de la misma manera, gracias a una interfaz de un solo método.

El concepto

El paquete io declara io.Reader: 

type Reader interface {
	Read(b []byte) (n int, err error)
}

Tú le das un slice de bytes y Read lo llena con datos, como mucho len(b). Devuelve n, cuántos bytes ha escrito de verdad, y un error. Cuando los datos se acaban, devuelve el error io.EOF (end of file, fin de los datos).

Lo normal es leer en un bucle: llamas a Read una y otra vez y usas los n bytes de cada vuelta, hasta que llega io.EOF. La biblioteca estándar está llena de tipos que cumplen esta interfaz: strings.Reader, os.File, bytes.Buffer y muchos más.

Animación: el texto «Hola, Reader!» son 13 bytes y b tiene sitio para 8. El primer Read copia 8 bytes y devuelve n = 8. El segundo solo encuentra 5: sobrescribe el principio de b y los 3 últimos bytes se quedan con restos de la vuelta anterior, por eso solo cuenta b[:n]. El tercero no encuentra nada: n = 0 y err = EOF.

Salida:

n = 5 err = <nil> b[:n] = "ader!"
n = 0 err = EOF b[:n] = ""

La primera lectura llena el slice entero. La segunda solo encuentra 5 bytes. La tercera ya no encuentra nada y avisa con EOF.

El error típico

Usar b donde hace falta b[:n]. Read no borra el slice: solo sobrescribe los primeros n bytes. En la segunda vuelta del ejemplo, b entero vale "ader! Re"; los tres últimos bytes son restos de la vuelta anterior.

El otro error es tratar io.EOF como un fallo. No lo es: es la forma normal de decir «ya no hay más». Compara con io.EOF y sal del bucle; cualquier otro error sí es un problema.
