Con las aserciones de la lección anterior puedes preguntar si una interfaz guarda un int. Pero si quieres hacer algo distinto para un int, para un string y para el resto, acabas con una cadena de if que repite la misma pregunta una y otra vez.

El concepto

Un type switch (un switch que compara tipos) prueba varios tipos en orden: 

switch v := i.(type) {
case int:
	// here v is an int
case string:
	// here v is a string
default:
	// here v has the same type as i
}

Dentro de cada caso

Se escribe como una aserción, pero con la palabra type entre paréntesis. Cada case nombra un tipo, y dentro de ese caso v ya tiene ese tipo, así que puedes usarlo sin convertir nada. También existe case nil, que se cumple cuando la interfaz está vacía.

Solo mira el tipo

Animación: i guarda la pareja (string, "hola"). El switch mira solo el tipo y prueba los casos en orden: case int no coincide y case string sí. Dentro de ese caso, v es un string, así que len(v) funciona e imprime 4 bytes.

Un error a propósito

Usa i.(type) fuera de un switch:

package main

import "fmt"

func main() {
	var i any = 42
	t := i.(type)
	fmt.Println(t)
}
./prog.go:7:7: invalid syntax tree: use of .(type) outside type switch

Cómo leer el error

./prog.go:7:7: invalid syntax tree: use of .(type) outside type switch

El principio del mensaje, invalid syntax tree, suena raro; lo importante está al final: .(type) solo vale en la cabecera de un switch. Si solo necesitas saber el tipo para imprimirlo, usa fmt.Printf("%T", i).

El error típico

Usar any cuando un tipo concreto basta. Si tu función solo trabaja con números, recibe un int: el compilador comprueba cada llamada por ti. Con any pierdes esa ayuda y tienes que repetir la comprobación con un type switch. Resérvalo para cuando de verdad puede llegar cualquier cosa.
