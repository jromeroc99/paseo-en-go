strconv.Atoi convierte un texto en un número. Pero si le das "cuarenta", no hay número que devolver. ¿Cómo te avisa? En Go no hay excepciones: el fallo es un valor más que la función devuelve.

El concepto

error es una interfaz del lenguaje con un solo método: 

type error interface {
	Error() string
}

Una función que puede fallar devuelve un error como último resultado. Si vale nil, todo ha ido bien; si no, algo ha fallado y Error() te dice qué. Por eso verás tanto este patrón: 

n, err := strconv.Atoi(s)
if err != nil {
	// handle the error and stop here
}

Para crear tus propios errores tienes errors.New("mensaje") y fmt.Errorf, que formatea como Printf. Y como error es una interfaz, cualquier tipo con un método Error() string es un error. Así puedes guardar datos en él.

Un error a propósito

Recibe el error y no lo mires:

package main

import (
	"fmt"
	"strconv"
)

func main() {
	n, err := strconv.Atoi("42")
	fmt.Println(n)
}
./prog.go:9:5: declared and not used: err

Ya conoces este mensaje: toda variable declarada tiene que usarse, y err no es una excepción. Aquí Go te protege de ignorar un fallo sin darte cuenta. Compruébalo con if err != nil.

El error típico

Llamar a fmt.Sprint(e) dentro del propio método Error(). Para imprimir e, fmt ve que es un error y llama a Error(), que vuelve a llamar a fmt.Sprint(e), y así sin fin hasta que el programa se detiene con fatal error: stack overflow. go vet lo detecta. Convierte antes: fmt.Sprint(float64(e)).
