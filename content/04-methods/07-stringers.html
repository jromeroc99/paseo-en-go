Imprimes una persona con fmt.Println y sale {Ana 42}. Es correcto, pero no dice mucho. Te gustaría que saliera Ana (42 años) sin tener que formatearlo a mano cada vez que la imprimes.

El concepto

El paquete fmt declara una interfaz muy pequeña: 

type Stringer interface {
	String() string
}

Un tipo con un método String() string es un Stringer: sabe describirse como texto. Cuando fmt va a imprimir un valor con Println, Print o %v, primero mira si es un Stringer. Si lo es, llama a String() y usa lo que devuelve.

Basta con el método

No tienes que registrar nada ni importar nada nuevo. Como viste con las interfaces, basta con tener el método. Es una de las interfaces que más vas a encontrar en Go, porque casi todos los tipos acaban imprimiéndose alguna vez: en un mensaje de error, en un registro o mientras buscas un fallo. Darles un String() claro te ahorra mucho tiempo.

El error típico

Declarar String() con receptor de puntero y después imprimir el valor: 

func (p *Person) String() string {
	return "Persona: " + p.Name
}

p := Person{"Ana"}
fmt.Println(p)
fmt.Println(&p)

Salida:

{Ana}
Persona: Ana

Por qué pasa

El método es de *Person, no de Person. Al pasar el valor p, fmt recibe algo que no es un Stringer y lo imprime a su manera. No hay ningún error ni aviso. Para String(), usa receptor de valor salvo que tengas un buen motivo.
