Tienes dos tipos, MyFloat y Vertex, y los dos tienen un método Abs. Quieres una variable que pueda guardar cualquiera de ellos y llamar a Abs sin preocuparte de cuál es.

El concepto

Una interface (interfaz) es un tipo que se define por un conjunto de métodos: 

type Abser interface {
	Abs() float64
}

Una variable de tipo Abser puede guardar cualquier valor que tenga un método Abs() float64. Al llamar a a.Abs(), se ejecuta el método del valor que haya dentro.

Sin implements

En Go no existe la palabra implements. Un tipo cumple una interfaz solo por tener sus métodos, sin declararlo en ningún sitio. Eso tiene una ventaja enorme: puedes escribir una interfaz para tipos que ya existen, incluso de otros paquetes, sin tocarlos.

Un error a propósito

Aquí el método tiene receptor de puntero, y guardas un valor:

package main

import "fmt"

type Speaker interface {
	Speak() string
}

type Dog struct{}
func (d *Dog) Speak() string {
	return "guau"
}

func main() {
	var s Speaker = Dog{}
	fmt.Println(s.Speak())
}
./prog.go:16:18: cannot use Dog{} (value of struct type Dog) as Speaker value in variable declaration: Dog does not implement Speaker (method Speak has pointer receiver)

Cómo leer el error

./prog.go:16:18: cannot use Dog{} (value of struct type Dog) as Speaker value in variable declaration: Dog does not implement Speaker (method Speak has pointer receiver)

El mensaje es largo, pero léelo en dos partes. Antes de los dos puntos: en la línea 16 no puedes usar Dog{} como Speaker. Después: Dog no cumple la interfaz porque Speak tiene receptor de puntero. Ese método es de *Dog, no de Dog. Guarda un puntero: var s Speaker = &Dog{}.

El error típico

Declarar una interfaz al lado de cada tipo «por si acaso», como harías con las clases en otros lenguajes. En Go la interfaz la declara quien la necesita, cuando la necesita, y suele tener uno o dos métodos. Si solo tienes un tipo, todavía no te hace falta una interfaz.
