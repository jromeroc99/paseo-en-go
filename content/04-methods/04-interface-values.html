En la lección anterior guardaste primero un MyFloat y después un Vertex en la misma variable. Pero entonces, cuando llamas a a.Abs(), ¿cómo sabe Go qué método ejecutar? La variable tiene que guardar algo más que el valor.

El concepto

Un valor de interfaz es una pareja: (tipo concreto, valor). El tipo concreto dice qué método se ejecuta; el valor es el que recibe ese método. Con %v ves el valor y con %T, el tipo.

El valor de dentro puede ser nil, por ejemplo un puntero *Box que no apunta a nada. La interfaz sigue sabiendo su tipo, así que el método se llama igual, con un receptor nil. Si el método lo comprueba, no pasa nada malo.

Otra cosa es una interfaz sin nada dentro, ni tipo ni valor. Esa sí es nil, y llamar a un método sobre ella no puede funcionar: no hay tipo que diga qué método ejecutar.

Un error a propósito

Este programa compila, pero falla al ejecutarlo:

package main

type Speaker interface {
	Speak() string
}

func main() {
	var s Speaker
	s.Speak()
}
panic: runtime error: invalid memory address or nil pointer dereference

Un panic es un error que ocurre con el programa ya en marcha, no al compilar. s no guarda nada, así que Go no tiene ningún método al que saltar. Antes de llamar a un método sobre una interfaz que puede estar vacía, comprueba que s != nil.

El error típico

Creer que una interfaz que guarda un puntero nil es nil. No lo es: en el ejemplo, d == nil da false en cuanto guardas b, porque la pareja ya tiene tipo. Una interfaz solo es nil cuando no tiene ni tipo ni valor. Lo verás de nuevo con los errores, que también son interfaces.
