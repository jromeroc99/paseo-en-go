Quieres un método que multiplique las coordenadas de un vértice por un número. Lo escribes como en la lección anterior, lo llamas y… el vértice sigue igual. No hay ningún error, simplemente no ha cambiado nada. ¿Por qué?

El concepto

Un receptor de valor, (v Vertex), recibe una copia del vértice. Todo lo que cambies dentro del método se pierde al salir. Un receptor de puntero, (v *Vertex), recibe la dirección del original, así que los cambios se quedan.

Go lo hace por ti

Con funciones tendrías que pasar el puntero a mano: Scale(&v, 10). Con métodos, Go lo hace por ti. Si v es una variable y Scale tiene receptor de puntero, v.Scale(10) se lee como (&v).Scale(10). Al revés también: si p es un puntero y Sum tiene receptor de valor, p.Sum() se lee como (*p).Sum().

Puntero o valor

¿Cuál eliges? Usa un receptor de puntero cuando el método tenga que cambiar el valor, o cuando el struct sea grande y copiarlo en cada llamada salga caro. Y elige una sola clase de receptor por tipo: si un método de Vertex usa puntero, que lo usen todos.

En la memoria

Animación: v vale {3 4}. ScaleCopy recibe una copia, la cambia a {30 40} y la copia se descarta al terminar: v sigue valiendo {3 4}. Scale recibe &v, sigue el puntero y cambia el original: ahora v vale {30 40}.

Un error a propósito

Llama a un método de puntero sobre un valor que no está guardado en ninguna variable:

package main

import "fmt"

type Vertex struct {
	X, Y float64
}
func (v *Vertex) Scale(f float64) {
	v.X = v.X * f
	v.Y = v.Y * f
}

func main() {
	Vertex{3, 4}.Scale(2)
	fmt.Println("hecho")
}
./prog.go:15:15: cannot call pointer method Scale on Vertex

Cómo arreglarlo

./prog.go:15:15: cannot call pointer method Scale on Vertex

Para añadir el &, Go necesita una dirección. Pero Vertex{3, 4} es un valor de paso que no vive en ninguna variable, y no tiene dirección. Guárdalo antes en una variable, v := Vertex{3, 4}, y llama a v.Scale(2).

El error típico

Escribir un receptor de valor en un método que cambia un campo. Es lo que hace ScaleCopy en el ejemplo: compila, se ejecuta y no cambia nada, porque trabaja sobre una copia. El compilador no te avisa. Si el método modifica el valor, el receptor lleva *.
